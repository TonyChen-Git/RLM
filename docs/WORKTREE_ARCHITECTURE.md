# Managed Worktree, Handoff, and Fork Architecture

Last verified: 2026-08-31

## Scope

Phase A implements the macOS Local ↔ Managed Worktree slice. It includes
linked-worktree `.git` pointer support, UUID-owned checkout lifecycle, exact
Task leases, transactional state transfer, launch recovery, Task Fork, and
truthful location UI. `ssh` and `futureCloud` remain reserved model values; no
Remote Runner or remote handoff is enabled in this phase.

## Ownership boundary

- A managed checkout path is derived only from its UUID below Application
  Support `LumaChat/AgentWorktrees/Checkouts`.
- `registry.json` is the authority for repository root, checkout path, branch,
  lifecycle state, and optional lease. A Session UUID or persisted workspace
  path alone is never sufficient authority to reuse or delete a checkout.
- A `WorktreeLease` binds a random lease ID, worktree ID, Task ID, acquisition
  time, and renewal time. Reuse by the same Task renews the same capability;
  another Task cannot steal it.
- Managed checkouts are persistent user-work containers, not disposable build
  cache. State-transfer scratch is kept under the repository `tmp` tree.
- General filesystem, search, and terminal tools receive checkout authority
  only. Validated Git metadata paths are used by the closed Git backend and are
  not added to model-visible filesystem authority.

## Repository layout

`GitRepositoryLayout` resolves normal repositories, linked worktrees,
separate-git-dir layouts, submodule-style pointers, and detached HEAD. Pointer
files are bounded, parsed without accepting arbitrary directives, and resolved
against Git's own fixed-command output. A forged, stale, linked, oversized, or
out-of-policy metadata path fails closed.

Git commands use fixed `/usr/bin/git` and disable hooks, credential helpers,
interactive prompts, fsmonitor, system/global configuration, and opportunistic
maintenance. Linked-worktree mutations are supported, but Git metadata Undo is
reported unavailable instead of fabricating a native `ChangeManager` record.

## Registry and lifecycle

`ManagedWorktreeService` serializes lifecycle mutations across actor
reentrancy. Its operations are:

- `create`: resolve the source repository, allocate a planned UUID, choose a
  collision-safe branch or detached checkout, add the worktree, persist its
  exact lease, and compensate partial creation on failure.
- `reuse` / `release`: validate the current registry record and checkout before
  renewing or releasing the exact capability.
- `inspect` / `list`: return durable state without turning a persisted path
  into authority.
- `remove`: require the matching lease when one exists; non-force removal is
  restricted to clean state. Force removal is used only by a committed
  handoff transaction with the exact journaled lease.
- `cleanup`: remove only old, clean, unleased worktrees.
- `repair`: reconcile missing, invalid, removal-pending, and UUID-shaped orphan
  paths. External deletion marks a record missing without silently releasing
  its lease.

Only untracked AppleDouble `._*` metadata generated by the external volume is
ignored for logical cleanliness and transfer enumeration. A tracked path with
the same prefix remains real repository content. Before non-force removal,
exact untracked AppleDouble sidecars may be cleaned with literal Git pathspecs;
no broad wildcard or recursive host deletion is used.

## State-transfer format

`WorktreeStateMigrator` captures:

- the exact HEAD object and symbolic branch reference;
- binary full-index staged and working-tree patches;
- every non-ignored untracked regular file;
- bounded explicit Task-owned supplemental ignored paths;
- absent-path tombstones and empty-directory manifests.

Paths, counts, patch bytes, payload bytes, file kinds, permissions, and parent
chains are bounded and validated. Symlinks and special files fail closed. The
snapshot fingerprint is a length-delimited SHA-256 identity over logical state.
Apply starts only on a proven-clean destination and verifies the resulting
snapshot. Reverse replacement uses an exact compare-and-swap against the Local
baseline and permits only same-commit or fast-forward movement; recovery alone
may perform the proven inverse.

Arbitrary ignored files are not copied. Only ignored paths already represented
by a Task change record are supplemental state. This avoids copying unbounded
build caches or secrets, and remains a documented Phase A limitation.

## Forward handoff: Local to Worktree

The durable order is:

1. Block Runtime activity and acquire the Task's location-mutation root lock.
2. Write a `prepared` journal with a planned worktree UUID.
3. Export transferable Undo history and capture the Local Git state.
4. Create the exact planned checkout and persist its Task lease.
5. Journal `destinationAllocated` with the concrete binding.
6. Apply and verify Git/supplemental state; import transferable history.
7. Journal `destinationReady`.
8. Atomically persist the Session binding, Local baseline, permissions rebased
   to the destination, and handoff provenance.
9. Journal `sessionCommitted`, then remove the journal.

Before step 8, failure compensates the created checkout and leaves the Session
Local. After step 8, the in-memory binding switches immediately and launch
recovery completes journal cleanup; the old checkout is never presented as the
active Task location.

## Reverse handoff: Worktree to Local

Reverse handoff never overwrites an independently changed Local checkout:

1. Validate registry path and exact lease, then lock both source and Local
   roots.
2. Re-capture Local with the original supplemental-root set and require the
   stored baseline fingerprint and symbolic reference.
3. Capture desired worktree state and a full Local rollback state over the
   union of owned paths.
4. Persist the rollback snapshot with UUID filename, exact byte count, SHA-256,
   schema, transaction ID, and logical fingerprint.
5. Write the reverse journal and Local destination binding.
6. Replace Local by compare-and-swap; journal `destinationReady`.
7. Atomically persist the Local Session binding; journal `sessionCommitted`.
8. Import transferable Undo history, re-capture the managed source to ensure it
   did not change after capture, and remove only the exact leased checkout.
9. Remove the recovery snapshot and journal.

If Local differs at step 2, no path is mutated. If replacement fails before the
Session commit, the rollback snapshot restores Local. If cleanup fails after
commit, the Local Task remains blocked for automatic launch recovery and the
source checkout is retained. A post-capture source change also retains the
checkout instead of force-removing newer data.

## Launch recovery decision table

| Durable Session | Journal state | Recovery result |
| --- | --- | --- |
| Source binding | `prepared` | Remove unused recovery payload/journal; no destination mutation was proven. |
| Source binding | destination allocated/ready | If Local equals desired, restore the exact rollback snapshot; otherwise preserve all evidence. |
| Destination binding | destination ready/committed | Verify destination state, transfer durable history, verify exact source capability/state, then finish cleanup. |
| Binding matches neither side | any | Fail closed, keep journal, checkout, lease, and recovery payload. |
| Duplicate journals for one Task | any | Treat as ambiguous and keep all evidence. |

Handoff, deletion, registry, Session, and recovery writes use synchronized
atomic replacement. Journal/recovery roots reject symbolic links in every
created path component. Recovery payload reads and removals are descriptor
relative, no-follow, size/digest/inode checked, and exclusive by transaction ID.

## Task Fork

`AgentTaskForkBuilder` creates a new Task identity with bounded conversation
context, Goal/Todo copies, workspace reference, latest checkpoint references,
and fork provenance. It resets Runtime state, steps, changes, permissions,
active processes, terminal state, and approvals. Writable Agent forks and forks
from an existing worktree receive a separately leased managed checkout through
the same planned-ID journal transaction. A read-only Local Plan may remain Local.

The sidebar and detail Task menus expose Fork, Move to Managed Worktree, and
Move Back to Local only when the Task state makes the transaction valid.
Location labels distinguish Local and Managed Worktree. Remote labels are not
presented as executable actions.

## Task deletion

Deleting a Task in a worktree writes an exact binding/lease intent before
deleting the Session. Once durable Session absence is proven, recovery releases
that exact lease. Deletion does not automatically remove the checkout because
it may contain user work; later cleanup remains clean-only.

## Verification

Focused suites cover repository layouts, lifecycle/lease conflicts, branch
collisions, repair, state migration and rollback, recovery integrity, journal
ordering/tamper/symlink cases, fork field policy, history reconciliation, and
Session ordering. `AgentViewModelWorktreeHandoffTests` exercises the full
Local → Worktree → Fork → Local chain, including external Local conflict,
persisted binding, distinct leases, journal cleanup, and source reclamation.

The release gate runs the complete XCTest suite in project-local isolated
paths. On 2026-08-31 it passed 344/344 Swift tests plus 5/5 release-archive
tests, built the production arm64 executable, signed the bundle, and verified
the ZIP's CRC, strict manifest, per-file content, canonical `0755`/`0644`
metadata, and AppleDouble exclusion. Clean extraction re-verified signature,
plist, executable and architecture. The release ZIP SHA-256 is
`b9736079bdfb686eb401f88c13d3ad26df75f28fd691e998121831ac09618fac`.

## Known limitations

- Remote execution and Local/Worktree ↔ Remote handoff wait for Phase F.
- Crash behavior is transactionally implemented and unit/integration tested,
  but process-kill, disk-full, and every-stage relaunch fault injection remain.
- There is no general worktree maintenance screen or scheduled cleanup yet.
- Created branches are retained after normal checkout removal.
- Arbitrary ignored files, symlinks, and special files are not migrated.
- Checkpoint references preserve immutable provenance; manifests are not
  rewritten to claim the new workspace identity.
- Linked-worktree Git metadata mutations do not have native file-level Undo.
